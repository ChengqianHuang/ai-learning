# 3.3 Mem0 记忆源码解析

## Mem0 是什么

**Mem0 是可以接入应用的开源记忆引擎。** 它提供从消息提取记忆、保存条目、按范围检索以及更正和删除的接口。应用可以配置提取模型、Embedding 模型、向量存储和重排器。它适合用来研究一个独立记忆模块如何负责「写入什么」和「怎样找回来」。 [Mem0 开源版概览](https://docs.mem0.ai/open-source/overview)

## 本篇读的是哪一层

本篇固定到提交 `f93aba4`，读取开源 Python SDK 同步 `Memory` 类的普通文本路径。重点是 `Memory.add()`、`Memory.search()` 和显式的 `update()`、`delete()`。这些方法由应用调用，模型最终收到哪些检索结果仍由应用组装。 [固定提交的 `Memory` 实现](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L487)

## 记忆机制综述

Mem0 先用**新消息、近期消息和同一范围内的相关记忆**给提取模型提供上下文。模型从新消息里提议新条目，SDK 再用向量与元数据保存它们。召回时，应用传入问题和查询范围，SDK 返回带分数的条目。 [提取上下文](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L918-L971) · [检索返回](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L1507-L1536)

| 数据 | 去哪里 | 用途 |
|---|---|---|
| 近期消息 | SQLite，按作用域留最近 10 条 | 帮提取模型理解指代与上下文 |
| 记忆正文、向量和范围元数据 | 向量存储 | 按范围检索、按条目 ID 维护 |
| `ADD`、`UPDATE`、`DELETE` 的记录 | SQLite 历史表 | 回查记忆如何变化 |
| 查询到的记忆 | `search()` 的返回值 | 由应用选择后放入下一次模型请求 |

## 写入时怎样形成条目

**第一步是确定范围。** `add()` 至少需要 `user_id`、`agent_id`、`run_id` 中的一项。SDK 把传入的标识写进条目元数据，也用于查询旧条目。任意业务元数据不能改写这些身份字段。接入多个用户时，调用方仍要根据已认证身份确定允许的范围。 [作用域与元数据](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L359-L404)

**第二步是搜旧记忆，再提取新记忆。** 默认的 `infer=True` 路径读取这个作用域近期保存的消息，再用本次消息检索最多 10 条已有记忆。单次 LLM 提取同时看到这三部分。提取提示要求从新消息形成条目，旧记忆主要用于识别已记录的内容，近期消息辅助理解指代。选择 `infer=False` 时，SDK 跳过提取，逐条为有效的非系统消息生成向量并保存。 [两种写入路径](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L881-L964) · [提取提示的职责划分](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/configs/prompts.py#L468-L521)

**第三步是向量化、去重并写入。** SDK 给提取出的文本生成 Embedding，按本批条目和已召回候选的文本哈希去重，再分配记录 ID 并尝试批量插入。哈希去重只覆盖这个候选范围和本批内容。语义重复的判断依赖前面的召回和提取模型。向量存储插入后，代码才写条目历史并维护实体关联。 [哈希去重与入库](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L993-L1076) · [结果确认与历史](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L1078-L1104) · [近期消息如何留存](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/storage.py#L257-L311)

### 发现新信息会怎样处理旧条目

这个提交的默认提取路径是 **ADD-only**。`add()` 的 docstring 还提到新增、更新和删除，但同步文本实现生成新条目，成功时返回的事件是 `ADD`。因此，一条新偏好可能和旧偏好同时存在。应用若要更正已有条目，可以按 `memory_id` 调用 `update()`，SDK 会更新正文、向量和历史。显式 `delete()` 会删除向量记录并追加删除历史。 [接口文档字符串](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L784-L795) · [实际返回的事件](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L1206-L1220) · [更新记录](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L2052-L2114) · [删除记录](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L2116-L2144)

## 检索怎样决定条目能否回来

`search()` 从 `filters` 接收范围标识。`_search_vector_store()` 先生成查询向量，扩大语义召回候选池。后端支持关键词查询时，额外计算 BM25 分数，同时可根据实体关联加分。**候选需要先通过语义召回和阈值，关键词和实体分数再影响排序。** 已过期的条目默认从候选里过滤。 [范围校验](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L1446-L1475) · [召回与评分入口](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L1642-L1701) · [评分器](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/utils/scoring.py#L60-L139)

## 应用接入时要观察的边界

- **更正与失效。** 添加、更新、过期过滤和删除是不同操作。需要唯一的现行事实时，应用要明确如何找到旧条目并处理冲突。删除搜索索引中的条目后，SQLite 删除历史仍可包含原正文。 [删除历史的字段](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L2122-L2142)
- **多处写入的一致性。** 向量条目、SQLite 历史和实体关联分别写入。源码里历史写入有独立的失败处理，因此存在条目已经可查询、历史尚不完整的可能。设计恢复或审计时，要区分条目持久化和后续记录是否成功。 [写入顺序与失败处理](https://github.com/mem0ai/mem0/blob/f93aba4b53241ccd9db32903cd19d1ff7f0066f0/mem0/memory/main.py#L1047-L1104)
- **检索结果的用途。** `search()` 返回的是候选条目。是否回查来源、如何处理条目间的冲突、最终哪些信息进入模型上下文，由应用决定。 [应用中的 `add` 和 `search`](https://docs.mem0.ai/open-source/overview)
