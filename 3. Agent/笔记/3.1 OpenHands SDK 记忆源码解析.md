# 3.1 OpenHands SDK 记忆源码解析

## OpenHands SDK 是什么

OpenHands SDK 是用于构建和运行软件开发 Agent 的开源 Python SDK。内置 `Agent` 负责模型与工具循环，`LocalConversation` 管理本地会话，`ConversationState` 保存进度并维护会话视图。 [SDK 组件说明](https://docs.openhands.dev/sdk/arch/agent)

## 本篇读的是哪一层

本篇沿用 2.1 中内置 `Agent` 的本地会话路径，追踪两条链路。**会话历史怎样变成一轮模型上下文，以及新会话怎样读到以前写下的经验。** 文末也标出了 Agent Server 项目记忆的入口，方便区分两种实现。源码固定在提交 `53ecc14`。 [2.1 OpenHands SDK 状态源码解析](2.1%20OpenHands%20SDK%20状态源码解析.md)

## 记忆机制综述

这里有两条相交的路径。当前会话的消息、工具动作与结果进入事件历史，SDK 沿当前分支生成 `View`，有需要时压缩再送给模型。跨会话的经验保存在独立的 Markdown 文件。新会话启用持久记忆后，索引文本会进入系统提示，成为新会话的一部分。

| 层次 | 记录或派生什么 | 何时使用 |
|---|---|---|
| 会话事件 `EventLog` | 消息、工具动作、结果、压缩事件等 | 恢复已有会话、查看行为轨迹 |
| 当前视图 `View` | 由当前分支和压缩事件还原的可用事件序列 | 每轮组装模型上下文 |
| 跨会话文件记忆 | 用户层和工作区层的 `MEMORY.md`，以及所引用的详细日志 | 新会话启动时加载索引，细节由 Agent 按需读取 |

先找持久化的记录，再找投影和注入点。**事件仍在日志中**表示可以回查，**事件在当前视图中**表示它可以参与模型上下文的组装。对这条文件记忆路径来说，**写入索引的信息**才会在启用该功能的新会话里自动加载。

## 会话内记忆从哪里来

### 1. 当前分支构成模型视图

`ConversationState.view` 沿当前分支末端追溯事件。分支直线追加时，缓存只追加新的尾部。切换到另一条分支或冷恢复时，从当前分支重建 `View`。`View.append_event()` 按事件类型分别处理。能转换成模型消息的事件进入视图，状态更新等内部事件通常跳过，压缩请求和压缩结果用于更新视图。 [视图缓存与重建](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/conversation/state.py#L509-L574) · [事件如何进入视图](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/context/view/view.py#L112-L164)

### 2. Condenser 调整视图

内置 `Agent.step()` 在调用模型前把 `state.view` 交给 `prepare_llm_messages()`。`AgentBase.condenser` 在该提交默认是 `None`。配置 `LLMSummarizingCondenser` 时，它可按事件数量、可用的 Token 限制或未处理的压缩请求触发。候选压缩区间会避开需保留的开头事件，并按视图允许的边界切分，避免截断成组的工具事件。 [Condenser 配置](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/agent/base.py#L288-L296) · [模型消息组装](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/agent/utils.py#L629-L653) · [触发条件](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/context/condenser/llm_summarizing_condenser.py#L140-L177) · [选择安全压缩边界](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/context/condenser/llm_summarizing_condenser.py#L331-L356)

摘要模型生成文本后，Condenser 返回一条 `Condensation`，记录移出的事件 ID、摘要和插入位置。`Agent.step()` 先发出这条事件并结束本步。下一步读取更新后的视图时，`View` 从可见序列移除相关事件，有摘要和插入位置时再插入摘要。压缩的变化在视图层生效，原事件仍保存在日志中。恢复时可以用日志里已有的 `Condensation` 重建压缩后的视图，复用当时记录的摘要。 [构造压缩事件](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/context/condenser/llm_summarizing_condenser.py#L249-L280) · [Agent 的压缩分支](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/agent/agent.py#L897-L913) · [摘要替换逻辑](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/event/condenser.py#L79-L96)

## 跨会话记忆怎样写入和加载

### 3. 写入由 Agent 通过文件工具完成

这条路径由 `AgentContext.load_memory` 开启，SDK 中默认关闭。启用时，默认系统提示的 `<MEMORY>` 段会告诉 Agent 在任务结束前写下值得保留的经验，整理重复或过期条目，并把长细节放到日期日志。Agent 根据这段提示选择记录内容，再用可用的文件工具写磁盘。文件能否写入取决于工具和工作区权限，提示本身不保证每次都会产生记忆。 [开关定义](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/context/agent_context.py#L137-L162) · [生成记忆维护指引](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/context/prompts/sections/static.py#L137-L176)

### 4. 加载只读两份索引，再进入系统提示

`LocalConversation` 首次调用 `send_message()` 或 `run()` 时初始化 Agent。启用持久记忆后，它按工作区路径调用 `load_memory()`，读取两份文件。

| 范围 | 读取路径 |
|---|---|
| 用户层 | 默认 `~/.openhands/memory/MEMORY.md`。配置 `OH_PERSISTENCE_DIR` 时，改用该目录下的 `memory/MEMORY.md`。 |
| 工作区层 | `<workspace>/.openhands/memory/MEMORY.md`。 |

读取顺序是用户层在前、工作区层在后。默认合计预算是 **6000 字符**，超限时按完整行从各层开头裁剪。加载器固定读取索引，日期日志由 Agent 根据需要通过文件工具阅读。索引不存在或读取失败时，初始化仍可继续。 [会话首次初始化](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py#L2026-L2072) · [会话读取记忆](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py#L1450-L1468) · [读取路径和裁剪规则](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/context/memory.py#L23-L106) · [用户持久化目录](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/utils/path.py#L32-L59)

索引文本进入运行时 `AgentContext.memory_context`，由 `MemoryContextSection` 渲染到动态提示的 `<MEMORY_CONTEXT>` 段。`Agent.init_state()` 生成 `SystemPromptEvent`，把动态提示放在静态提示之后，作为同一条系统消息的第二个内容块。模型因此能读到索引，而提示仍将这些文件内容标明为未经验证的线索。 [动态提示渲染](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/context/prompts/sections/dynamic.py#L79-L100) · [生成系统提示事件](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/agent/agent.py#L704-L725) · [转换为模型消息](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/event/llm_convertible/system.py#L72-L85)

## 新会话和旧会话的恢复边界

**新会话从文件读索引，已有会话可以沿用保存的提示事件。** 官方指南说明，解析后的 `memory_context` 不写入 `base_state.json`。源码中，`AgentContext` 对该字段设置了 `exclude=True`，所以它不会随 Agent 配置序列化。 [官方持久化记忆说明](https://docs.openhands.dev/sdk/guides/persistent-memory) · [配置字段排除序列化](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/context/agent_context.py#L153-L163)

本地事件日志还有一条独立的保存路径。在该提交的默认本地事件回调中，渲染后的 `dynamic_context` 是 `SystemPromptEvent` 的普通字段，事件日志会把事件序列化后写入底层存储。正常恢复时，如果 `Agent.init_state()` 已找到原来的系统提示事件，它会直接返回。因此在启用文件型事件持久化的这条路径上，删改 `MEMORY.md` 后，旧日志里的提示仍可能保有之前的内容。这个结论来自该提交的本地读写路径，与不同部署是否持久化事件是两个问题。 [系统提示事件字段](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/event/llm_convertible/system.py#L29-L41) · [默认事件回调](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py#L526-L533) · [事件序列化](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/utils/models.py#L262-L285) · [保存事件](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/conversation/event_store.py#L352-L362) · [恢复时复用原提示事件](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/agent/agent.py#L651-L672)

上游测试提供了两个直接的核对入口。`test_load_memory_flag_injects_memory_into_system_prompt` 检查启用开关后，文件内容进入 `SystemPromptEvent.dynamic_context`。`test_load_memory_truncation_keeps_both_tier_headers` 检查预算不足时保留两个层级标题，并丢弃超限层的开头内容。 [系统提示注入测试](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/tests/sdk/conversation/test_local_conversation_memory.py#L69-L99) · [索引截断测试](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/tests/sdk/context/test_memory.py#L86-L104)

## Agent Server 的项目记忆属于哪条路径

同一仓库的 **Agent Server** 还提供 `ProjectMemoryStore`，按服务端项目 ID 保存索引和主题文件。创建项目会话时，服务端读取索引，将内容经项目上下文注入 `<PROJECT>`。启用的项目工具可以读写主题文件，存储层用版本值检查并发修改。这条路径的存储范围由项目 ID 决定，前文所读的本地 SDK 文件记忆则按用户持久化目录和工作区路径定位。 [项目索引读取](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-agent-server/openhands/agent_server/project_service.py#L219-L235) · [项目提示渲染](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-sdk/openhands/sdk/context/prompts/sections/project.py#L287-L296) · [项目记忆版本检查](https://github.com/OpenHands/software-agent-sdk/blob/53ecc14a8a039faed26fc045b813321bad8e594f/openhands-agent-server/openhands/agent_server/project_memory.py#L112-L147)
